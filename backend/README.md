# backend/

FastAPI application. Single process, multiple internal `asyncio` tasks (API server, PLC poller, background workers) — see [ARCHITECTURE.md §3.5](../docs/architecture/ARCHITECTURE.md#35-single-backend-process-not-split-microservices) for why this isn't split into multiple containers.

| Path | Purpose |
|---|---|
| `app/api/v1/` | FastAPI routers — **implemented**: `auth` (login/refresh/logout/me), `live` (current status + per-sensor), `history` (+ CSV export), `alarms` (list/filter + acknowledge + `/events`), `sensors` (CRUD, RBAC), `settings` (Configuration + AlarmRule updates, admin-only), `users` (admin-only CRUD), `system` (health via psutil). `app/api/deps.py` holds `get_current_user`/`CurrentUser`/`require_roles` (RBAC), `app/api/v1/router.py` aggregates them under `/api/v1`. |
| `app/core/` | Cross-cutting setup: `config.py` (`pydantic-settings`), `database.py` (async engine/session, SQLite PRAGMAs), `security.py` (bcrypt hashing + JWT create/decode), `time.py` (`utcnow()` — see note below on why this exists), `rate_limit.py` (`SlidingWindowRateLimiter` — in-memory login rate limiting), `logging_config.py` (`JsonFormatter`/`configure_logging()` — structured JSON logs). |
| `app/models/` | SQLAlchemy ORM models (dialect-agnostic — see [ARCHITECTURE.md §3.2](../docs/architecture/ARCHITECTURE.md#32-database-sqlite-now-postgresql-ready-later)). |
| `app/schemas/` | Pydantic request/response schemas — **implemented** for every resource (`auth`, `user`, `sensor`, `reading`, `alarm`, `system_log`, `configuration`, `system`). Nothing crosses an API or service boundary as a raw dict. |
| `app/repositories/` | Repository pattern — all DB queries live here, injected into services/routers via `Depends`. Swapping SQLite→PostgreSQL touches this layer, not callers. |
| `app/services/` | Business logic — **implemented**: `validation.py` (`ReadingValidator` — range/rate-of-change/staleness), `alarm_engine.py` (`AlarmEngine` — threshold/boolean evaluation, hysteresis, debounce, acknowledge — `evaluate()` returns the changed `Alarm` or `None` so callers know what to broadcast), `ingestion.py` (`ReadingIngestionService` — the poller-to-database-to-alarms-to-WebSocket glue), `system_health.py` (shared by the REST endpoint and the periodic WS broadcast), `startup.py` (`record_startup()`/`mark_clean_shutdown()` — clean-restart vs. crash/power-loss detection via a marker file, logged as a `SystemLog` row). |
| `app/plc/` | PLC communication layer — **implemented**: `PLCClient` interface (`base.py`), `S7PLCClient` (snap7), `ModbusPLCClient` (pymodbus), `SimulatedPLCClient` (no-hardware-needed dev/test double), tag map loader (`tags.py`, backed by `config/plc_tags.yaml`), raw→engineering `scaling.py`, reconnect/backoff `connection.py`, tiered `poller.py`, and a `factory.py` picking S7 vs Modbus from `PLC_PROTOCOL`. See [ARCHITECTURE.md §4](../docs/architecture/ARCHITECTURE.md#4-plc-communication-layer). |
| `app/realtime/` | WebSocket layer — **implemented**: `connection_manager.py` (`ConnectionManager` — in-process pub/sub broadcast, created once in `create_app()` so `/ws/live` works independently of the PLC lifespan; `connect()` registers an *already-accepted* socket, since accepting is `/ws/live`'s job), `router.py` (the `/ws/live` endpoint — always `accept()`s first, then reads a JSON `{"token": "..."}` first message as the auth handshake, since a `?token=` query param would leak into proxy access logs/browser history), `health_broadcaster.py` (periodic `system_health` frame, skipped when nobody's connected). See [ARCHITECTURE.md §7](../docs/architecture/ARCHITECTURE.md#7-rest-api-design) "WebSocket". |
| `app/workers/` | Background asyncio tasks — **implemented**: `retention.py` (`RetentionWorker` — hourly/daily rollup then raw-row pruning), `backup.py` (`BackupWorker` — SQLite online-backup API + 14-daily/12-monthly rotation), `atlas_sync.py` (`AtlasSyncWorker` — optional, disabled unless `ATLAS_CONNECTION_STRING` is set, outbox pattern on `SensorReading.synced_at`), `scheduler.py` (`run_daily` — a plain sleep-until-next-run loop for the two daily jobs, no scheduling library needed for just two jobs). |
| `alembic/` | Database migrations, generated from `app/models`. |
| `tests/unit/` | Unit tests per module (repositories, services, PLC client against a simulator, alarm engine, WebSocket connection manager). |
| `tests/integration/` | Full pipeline tests: simulated PLC → poll → validate → store → API/WebSocket. |

Implemented (roadmap Modules 1-9, all complete): `app/models`, `app/repositories`, `alembic/`, `app/core/`, `app/plc/`, `app/services/`, `app/api/`, `app/schemas/`, `app/realtime/`, `app/workers/`, and `app/main.py` (the FastAPI app itself — `create_app()`, CORS, a global exception handler, and a `lifespan` that runs `record_startup()`, wires PLC → Poller → Ingestion → Alarm Engine → WebSocket broadcast, starts the retention/backup/Atlas-sync workers, and calls `mark_clean_shutdown()` on the way out, per §3.5 and §14). Verified by booting a real `uvicorn` process and exercising it with `curl` (login, `/live`, `/sensors`, `/system/health`), a real `websockets`/Playwright client connecting to `/ws/live` (confirming the token never appears in the connection URL), a real SIGTERM/reboot cycle (confirming the clean vs. unclean `SystemLog` restart entries), and confirming the background workers log correct startup state (retention/backup schedule, Atlas sync enabled/disabled) — not just the test suite.

**Why `app/core/time.py` exists:** SQLite (via SQLAlchemy) silently strips timezone info from stored `DateTime`s on read-back — writing an aware `datetime.now(UTC)` and reading it back gives a naive value. Comparing a fresh aware "now" against that naive value raises `TypeError`. Rather than special-case every comparison, the whole app standardizes on `utcnow()` (naive, but always UTC) for anything that's stored or compared against stored timestamps.

**Why the WebSocket tests in `tests/unit/test_ws_live.py` are plain sync functions:** Starlette's `TestClient.websocket_connect()` runs the ASGI app in a background thread with its own event loop. Driving it from inside a pytest-asyncio `async def` test deadlocks the moment the server side of the connection stays open — confirmed empirically, even a bare connect-then-exit hangs indefinitely under `asyncio_mode = auto`. Plain sync tests (with `asyncio.run(...)` for the async setup/broadcast pieces) sidestep the nested-loop hazard entirely; multi-client broadcast behavior is tested separately and more robustly in `test_connection_manager.py` using fake WebSocket doubles, since two real `TestClient` portal threads sharing one in-memory SQLite connection is its own (unrelated) fragility.
